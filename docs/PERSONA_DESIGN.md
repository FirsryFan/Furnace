# Persona：用户自我描述（轮次一百七十二）

用户原话（2026-10-25）:

> 提供一个 persona 功能，可以放在认知模型内部或者外部，或者说是外部但是有相互作用。让用户自己描述自己。

本文记录这一片的口径：**它是什么、存在哪、怎么起作用、边界在哪**。实现行号以
`app/lib/data/database/database.dart` / `tables.dart` / `settings_repository.dart` /
`agent_loop.dart` / `user_persona.dart` 为准（写本文时已核对）。

## 1. 一句话

一段**用户自己写的原话**（最多 8000 字），存在本机设置表里；AI 对话每一轮把它作为
背景拼进系统提示，其余场景（解题/整理/组卷）不读它。位置在「认知模型之外」——
它不是认知模型算出来的读数，也不改变任何参数；但它**与认知模型有一处相互作用**：
认知模型页顶部有一张卡片显示这段描述和编辑入口，设置页也有一个入口。

## 2. 为什么不是结构化档案

用户要的是"自己描述自己"，不是让应用逼他填五个字段（年龄/目标/习惯/弱点）。
结构化档案有两个代价：

- **表达力**：用户想说"我数学想冲 120 但计算总粗心"，字段里没有地方放这种因果；
- **改一个字要重写整段**：如果存的是"摘要后"的结构，任何一次编辑都要求模型重新
  抽取，抽取结果不可逆、还可能比原文更不像用户。

所以库里存**用户的原话**（只做空白归一化，见 §3），不存模型摘要，也不在写库路径上
截断。长度为上限 8000 字由编辑页挡；截断会悄悄丢用户的话，不干。

## 3. 领域契约（`app/lib/domain/services/cognitive/user_persona.dart`）

纯 Dart、零 Flutter/drift 依赖：

| 符号 | 契约 |
| --- | --- |
| `kUserPersonaMaxChars = 8000` | 编辑页的硬上限（按归一化后的 `String.length`） |
| `normalizeUserPersona(raw)` | CRLF/CR → LF；逐行去行尾空白（含半角空格、制表符、VT、FF、U+00A0、U+3000）；整体 trim。**中间空行与非首行行首缩进保留**（那是用户排版的一部分） |
| `userPersonaForStorage(raw)` | 归一化后为空 → `null`，否则归一化文本。**不截断** |
| `userPersonaIsPresent(raw)` | 归一化后非空 |
| `userPersonaTooLong(raw)` | 归一化后长度 > 8000 |
| `userPersonaPromptBlock(raw)` | 空 → `''`（**提示字节不变**）；非空 → 固定引导行 + `\n` + 归一化文本，结尾不带换行 |
| `userPersonaPreview(raw,{maxChars=120})` | 折叠全部空白为单空格；超长截断且**省略号算在 maxChars 内**。只给页面看，不参与存储/提示 |

引导行（`_promptLeadLine`，测试里用字面量钉死）:

```
用户对自己的描述（作为背景来理解用户；不要复述这段话，也不要因为提到就刻意迎合）：
```

"不要复述、不要刻意迎合"是这段的一部分：persona 是**背景**，不是要求模型每句话都
提到用户是谁，也不是让模型为了讨好用户而放弃正确答案。

## 4. 存储（schema v35）

`local_settings.user_persona`：TEXT，可空。**NULL = 没写过**（不是空字符串；空白在
仓库层就存成 NULL，所以"没写"只有一种表示）。迁移只补列、不回填——回填会把当时还
不可能存在的内容写成一条假的自我描述（与 `tagTreeSortMode` / `reviewReminderMinutes`
同一个契约，见 [DATA_MODEL.md](DATA_MODEL.md) §24）。

读写（`SettingsRepository`）：`getUserPersona()` 原样返回库里值（不 import 域层）；
`updateUserPersona(text)` 先 `ensureSettings()`（设置行懒创建，不先确保会写 0 行），
trim 后空 → NULL。长度上限**不在仓库层**：仓库若静默截断就丢了用户的话，超长由编辑页
用 `userPersonaTooLong` 拦。

## 5. 注入（AI 系统提示）

`AgentLoop._turnTools()` 每一轮先读 persona，再拼系统提示
（`app/lib/features/ai/domain/agent_loop.dart:1151` 起）：

```
你是一位……（固定 base）
今天的日期是 YYYY-MM-DD。
[persona 段落]            ← 只有非空时才有这一行
规则：
1. …
```

三条硬口径：

1. **空 persona = 逐字节不变**（`_baseRules('')` 与加 persona 之前的提示完全相同）。
   这不是洁癖：与 skills 开关「关掉时提示与旧行为一致」是同一个承诺——任何模型行为
   变化都必须能归因到用户写了东西。
2. **位置在日期之后、规则之前**：日期是事实，persona 是背景，规则最后读——不能让用户
   的自我描述盖过系统规则的位置。
3. **读失败不阻断**：读 DB 抛错（缺列/文件损坏）就当作没有 persona，这一轮照常回答。

## 6. 界面

- **设置页「自我描述」入口**（认知模型入口之后）：副标题是 persona 前 40 字预览，
  没写过时显示一句说明；点进去是编辑页。
- **编辑页**：多行输入框 + 字数计数（`N / 8000`）+ 说明 + 隐私说明；超长时提示并
  禁用保存；保存成功/失败都有 SnackBar；已写过时多一个「清除自我描述」按钮，清除要
  二次确认（不可撤销）。
- **认知模型页顶部卡片**：显示前 160 字预览（空态显示「还没有写过自我描述」）+ 编辑
  按钮。这是"外部但与认知模型相互作用"的落点：persona 不是认知模型的一项读数，但
  用户在看认知模型时能一眼看到自己对 AI 说的话，并能就地改。

## 7. 隐私与作用范围

- 只存在本机 SQLite，不上传、不同步、不进导出文件（题库包/备份都不包含设置表）。
- 只用于 **AI 助手对话**的系统提示。解题思维链、拍照整理、组卷、闪存卡等流程的提示词
  **不读 persona**——那些是题目数据驱动的输出，混进用户自述会让"这道题为什么这样解"
  变得无法解释。以后若要让 persona 影响某个具体流程，必须先写清那个流程的口径。
- 清除后立即失效：下一轮系统提示不再含这段（不需要重启）。

## 9. 仍未做（写下来免得下次重新争论）

- **没有**导入/导出、跨设备同步、备份（设置表不在题库包里）；
- **没有**结构化字段（目标/习惯/弱项分开填）——刻意的，见 §2；
- **没有**逐对话开关（不能"这段对话不读 persona"）；
- **没有**在编辑页做"AI 帮你润色"——那会让用户的原话变成模型的话；
- **没有**把 persona 注入解题/整理/组卷提示（§7 的理由）；
- 真机上长文本输入、超长提示滚动的视觉未手测；
- 8000 字上限是拍的，不是标定值。
