# MindNet 初始输入与反馈迭代设计

## 1. TR 编号

- TR 是 Furnace 内部全局题目编号，对应 questions.serial_no（显示为 TR-xxxxx）。
- 不是“本册第几题”，也不是科目内编号。
- 资料、DAG、答题反馈、MindNet 任务都只用 TR 关联。

## 2. MindNet 初始信息输入

冷启动不能凭空猜。初始输入分四层：

### A. 用户自述
- 年级、目标、当前水平、强弱科、时间预算、学习偏好。
- 来源：用户人设/自我描述/设置页。

### B. 题库结构
- 知识点 knowledge_points、知识边 knowledge_edges、题库标签 tags。
- 每道题映射到知识点/标签；没有映射的题先不参与诊断。

### C. 诊断结果
- 第一份精研资料或专门诊断卷的作答；
- 每题记：正确/部分/错误、用时、是否看提示、信心。
- 没有诊断时，cognitive_priors 只能给弱先验，并标 calibrated=false。

### D. 先验参数
- 每个知识点一个初始状态：r0（初始记住概率）、d（衰减）、fluency、n（伪观测数）、source。
- 每个能力一个初始 mean/uncertainty；来源标 seed。
- 初始不确定性要大；不要伪装成精确测量。

## 3. 反馈事件

资料做完后必须产生不可变反馈事件：

- TR
- 结果：correct / partial / wrong
- 用时
- 是否使用提示/看了多少
- 自评信心
- 错误类型：概念/计算/审题/迁移/表达
- 关键步骤卡点
- 用户备注

事件只追加，不覆盖；后续 MindNet 更新由事件推导。

## 4. MindNet 更新

每条反馈更新：

1. 题目对应知识点的掌握状态；
2. 相关能力估计（mean/uncertainty）；
3. 标签/知识点传播（knowledge_edges）；
4. 下次资料选题的权重；
5. 复习时间/优先级。

更新必须记录来源事件 id，可回放。

## 5. 共同进化闭环

资料 → 作答 → 反馈事件 → MindNet 更新 → 下一次选题/提示/难度 → 新资料。

每一轮都保留：
- 旧信念快照；
- 新信念；
- 变化原因（哪条反馈）；
- 下一轮选择依据。

## 6. 与资料生产的关系

- 资料生产前：用 MindNet 先验选主题/难度，但允许探索。
- 资料生产中：solver trace 与 MindNet 扩散对照，决定提示/DAG 分支。
- 资料生产后：用户反馈写回 MindNet，不把“做完”当成“学会”。

## 7. 验收

- 初始种子有来源，不伪造精确值；
- 每条反馈能追到 TR 和用户操作；
- MindNet 更新能解释“为什么这个知识点变了”；
- 下一份资料能引用上一轮反馈；
- 用户能看到自己的信念变化，而不是黑箱。
