## D01 产品定位与目标用户

- **决定**：保持"面向高密度信息工作者的本地优先生产力工具"；当前唯一真实用户是高三学生；内测小组只审内容。
- **依据**：用户 2026-11-01："面向高密度信息工作者的本地优先生产力工具，这个是合适的"；"内测小组只审内容、不审 App 交互…做按用户版本即可"。
- **影响**：不把"高三/学生"写死成产品身份；不做多用户、账号、云同步；反馈闭环 = 用户本人 + 内容侧内测小组人工审核。
- **状态**：已确认（长期有效）。

## D02 平台分工与隔离

- **决定**：
  - Android = 日常轻任务（设备优势 + 任务轻量 + AI 内容导向）：收题/拍照、闪存卡、题库浏览与自测、Time/Thread、AI 对话与轻工具、提醒。
  - Windows = 重任务：文档产出（docx）、批量组卷、材料生产、skill 脚本、大批量文件操作、未来的重 AI 任务。
  - **不可用任务直接不给入口**（不置灰、不排队）——"本来就没设计对应位置，肯定不会有对应板块"。
  - 跨端靠文件传递（.tqb / .tfpkg / .docx / .kpak），因为无云同步。
- **依据**：用户 2026-11-01 第三轮："android 为主并不是 android 功能更强，而是受限于手机的设备优势，以及任务类型的轻量性质…有些任务仅限 Windows 端，这里需要做好隔离"；"不可用任务就直接不给入口就行了"。
- **影响**：
  - 29 个 AI 工具当前 `availableOnCurrentPlatform` 全为 true（等于没有隔离），需要"工具级平台声明 + 当前平台过滤"。
  - 需要"任务能力矩阵"：任务类型 → 平台 → 入口/产物/降级方式。
  - AI 是"内容导向而非平台导向"：平台只决定在哪执行，不决定 AI 能理解什么。
- **状态**：机制设计开始（平台能力矩阵与门控基础在推进）。
- **待办**：能力矩阵定稿；Windows-only 能力清单；跨端产物消费路径。

## D03 MindNet 是一等用户模型引擎（撤销"MindNet 并入标签"）

- **决定**：**撤销 2026-09-08 的"Mindnet 并入标签"决策**（DESIGN_BLUEPRINT §2.8 / 决策索引 2.8）。
  - 标签 = 组织与检索体系（内容域、筛选、卡组范围），保持现状；
  - MindNet = **用户模型引擎**：刻画用户的记忆、思维、判断，产出个性化题目推荐/编辑/扩展、任务安排、闪存卡推送、精力预测；
  - 用户状态**全权由 MindNet 处理**；MindNet 能力不够就扩展 MindNet，而不是另起一套用户模型；
  - MindNet 本身也不完整（同样是用户带 agent 开发的项目），不完整是正常状态。
- **依据**：用户 2026-11-01："MindNet 并入标签是极大的错误。MindNet 的设计极其精妙…"；"用户状态全权由 MindNet 处理。如果 MindNet 不够，就让 MindNet 扩展，收纳更多功能"。
- **现状证据**：仓库已移植 MindNet 并接了一部分，但 MINDNET_ROADMAP.md 自述根因："我们把 MindNet 当成'给每张卡算两个数'的函数用，而它设计成'一次运行 = 一批事件 → 一份报告'的引擎。"
  - 已接：tierA 记忆层 + tierB 快层、卡点诊断/反事实、顾问式排序 bands、元认知、节律读数、控制层 V(π)/今日计划、材料摄取/照片转写（部分）、线索边、题目评估。
  - 未接：`run/1` 事件流五类动作、幂等 run_id 与存档回退、`result/1` 完整报告、17 条指令库完整排序、参数标定、反馈微调、插件架构用户开关等。
- **影响**：
  - 顶层新增 MindNet 模块（本轮已接 shell）；评测板块（v41 的 10 能力/9 参数）、persona、能力画像都应并入 MindNet 作为输入/输出，而不是并行系统；
  - 事件层（全量记录、幂等、可回放）是 MindNet 的地基（见 D06）；
  - 消费侧（找题排序、Thread 排序、闪卡推送、题目扩写）统一从 MindNet 读数取数；
  - 旧 `MindMaps`/`MindNodes` 表与 `.kpak` 的 mind_map 计数保留，可作为 MindNet 图数据载体复用，不删除。
- **状态**：顶层入口已接（MindNetPage）；设计文档在写；引擎实现分阶段。
- **待办**：MindNet 设计文档定稿；`run/1` 事件层 schema；报告落库；评测/persona 并入方案；消费侧接线顺序。

## D04 AI 是一等模块；"内置 DSH"= 具备能力而非打包运行时

- **决定**：
  - AI 是独立功能模块（入口常驻，不再"配了 key 才出现"）；未配置时页面自己给配置引导；
  - "内置 deepseek harness"理解为**让 Furnace 自身具备相应能力**（文档生成、组卷网检索、材料处理、多 skill 任务），不是把 DSH 运行时打包进安装包；
  - DSH 面向的、Furnace 没有使用场景的能力**不复刻**；**软件不能太大**；
  - 需要更多 skill、更多任务类型；能力按需内建，成熟后再考虑 sidecar/混合运行时。
- **依据**：用户 2026-11-01："DSH：CA，我觉得。我说内置 dsh 的意思是要有相应能力。对于 dsh 面向的更多没有使用场景的能力自然不必复刻。我们的软件不能太大。"；"若仅认为 AI 是一个附属，则不能发挥 AI 的能力。应把其当作独立功能模块…该观点与 MindNet 的运用同理。"
- **影响**：短期不做 Node/DSH sidecar；优先扩展 Dart 侧 AgentLoop + 工具 + 技能容器；平台门控与技能能力声明是前置；文档生成/组卷网检索作为"内建能力"排期。
- **状态**：AI 入口常驻已做；平台门控基础在推进；能力清单未定。
- **待办**：能力清单（Windows-only vs 双端）；skill 容器能力扩展；docx 通用化；组卷网桥。

## D05 题库四层成熟度与 AI 自主"整"

- **决定**：题库采用四层成熟度（用户原话）：
  1. **原始数据**：用户拍照图片等原始数据；
  2. **未加工题**：AI 根据图片去组卷网找题，或定期任务从组卷网收集题目，保存题目/答案/解析原文数据；
  3. **已加工题**：题目经 MindNet 等完整评价、标签流程、题目分析、扩展设计，深度融入 Furnace；
  4. **成熟题目**：AI 制作题单时结合更多内容进一步扩展链接、内容精简加工、多题目组织设计，形成成熟题目供用户学习。
  - **"整"的步骤由 AI 自主完成**；人工（内测小组）只在内容审核点介入。
- **依据**：用户 2026-11-01 第三轮题库层次说明。
- **影响**：
  - `questions` 需要成熟度/阶段字段与原始数据 provenance（schema 设计另立迁移）；
  - 需要 pipeline runs/actions 记录（AI 自主流程可审计、可回滚）；
  - M2-c 材料容器 + M2-d 材料练习记录并入该管线；
  - 组卷/题单/Word 属于"成熟题目"层的产物；
  - .tqb 未来可携带成熟度字段（v2 契约）。
- **状态**：设计文档在写（docs/QUESTION_MATURITY_PIPELINE.md），实现待设计评审。
- **待办**：设计评审；schema v43 规划；AI 工具编排；内测小组审核接口。

## D06 全量记录、阈值结论

- **决定**：学习相关行为与结果**全量入库**，不因"孤立单题"丢弃：
  - 记录：作答/错因/用时/岔路/重做历史、曝光（看了没测）、复习、任务完成、AI 写操作（已有 `ai_actions` 台账）、题目阶段流转；
  - 结论：用样本量门槛（如现有 `kCapabilityMinSamplesForConclusion = 3`）决定"能不能下结论"，而不是在记录阶段过滤；
  - 隐私：数据全部本地；不做行为上报。
- **依据**：用户纠正："孤立单题错→噪音不处理：其实是要处理的，要记录，否则没有数据积累何来统计结果？"；记录边界用户授权我按成熟工程实践判断。
- **影响**：M2-d 练习记录与 MindNet `run/1` 事件流共用同一事件底座；记录与诊断解耦（先记录、后归因）。
- **状态**：原则确定；事件层设计随 MindNet 设计推进。

## D07 知识库下沉设置 + 启用/禁用/卸载

- **决定**：
  - 删除顶层"知识库"目的地；设置页内新增「知识库」子页，用于管理已导入知识包：启用/禁用、卸载、导入导出、查看条目统计；
  - **启用/禁用**：写 `knowledge_packages.enabled`（schema **v42**，可空，NULL=启用）。本轮只做管理状态，**不做内容级隐藏过滤**（跨查询散改风险大，后续单独设计）；
  - **卸载**：删除包记录与 `package_items` 归属记录，**不删除**由它导入的知识点/闪存卡/标签（UI 明示）；如需"连内容删除"另立高风险确认。
- **依据**：用户 2026-11-01："知识库功能很'何意味'，应当只在设置界面内部用于管理知识库（启用禁用卸载相关数据等等）和导入导出文件"；"知识库要能启用禁用"。
- **状态**：schema v42 已落；repository 层与 UI 在实现；设置入口已接。
- **待办**：内容级隐藏是否要做；"连内容删除"是否需要。

## D08 Windows 数据目录迁到 E 盘

- **决定**：
  - Windows 端数据默认根目录 **E:\Furnace\data**（路径名可后续做成设置项）；
  - 用 `<appSupport>/storage_root.txt` 极小指针文件记录数据根（解决"库位置不能存库里"的启动顺序问题）；
  - 首次启动一次性迁移：复制不删旧、目标已有库则跳过、失败回退旧目录不写指针；
  - 题库包备份等随数据根；Android 继续用 app support 目录。
- **依据**：用户 2026-11-01："%APPDATA%\FirsryFan\Furnace\furnace.db，请你移动到 E 盘某目录下，避免占用 C 盘空间"。
- **状态**：实现中。
- **待办**：设置页展示路径/更换路径；迁移完成提示。

## D09 精力水平由 MindNet 预测并自主设定

- **决定**：Thread 的精力水平不再只靠手填：MindNet 根据历史完成记录、复习记录、时间节律与近期负荷做**记忆化预测**并自动设定，允许用户手动覆盖；预测带来源与置信度，未标定的部分明确标注。
- **依据**：用户 2026-11-01："精力水平也可以根据用户水平记忆化处理完成预测和自主设定"。
- **状态**：纯逻辑实现中（本轮）；Thread UI 接线后续。
