# Furnace 资料入库设计：按题，不按页

> 结论：PDF/Word 原始资料只做“来源文档”；真正入题库的是切分后的题目，不是每一页。
> 当前把每一页 PDF 当题目上传的做法，必须废弃。

## 1. 数据分层

### source_document
- 一份 PDF/DOCX/图片：文件名、路径、科目、年份、卷别、来源类型、页数、hash。
- 只登记一次，不进入 questions 表。

### source_page（可选）
- 只在需要保留版式/图形时存页面图。
- 用途：裁题图、裁装置图、人工核对；不是题目记录。

### question_unit
- 题干、题型、选项、答案、解析、知识点、难度、来源、fingerprint。
- 以“题号/小题”为单位，不以“页”为单位。

### figure_asset
- 只存被题目真正引用的图：装置图、函数图、表格、流程图。
- 一题多图时记顺序；不把整页当图塞进题干。

### answer_unit / analysis_unit
- 官方答案与官方解析分别存；
- 原文逐字保留；模型改写的“可读化推导”另存，不能覆盖官方原文。

## 2. 处理流水线

1. 登记文档：路径、hash、年份、卷别、科目、页数。
2. 文本抽取：DOCX 用 python-docx；PDF 用 PyMuPDF；扫描页才 OCR。
3. 题号切分：识别“1．/（1）/ 一、”等边界，切到题目级；保留原题号。
4. 答案/解析对齐：解析卷按题号合并；找不到官方答案的题标“官方答案缺失”，不生成假答案。
5. 图裁切：只裁题干真正引用的图；保存 figure_asset；记录 bbox 与来源页。
6. 去重：题干 fingerprint + 来源；同题异卷保留来源关系，不重复建题。
7. 质量审查：答案、解析、图、知识点、难度五项；缺项进“待重生成/待补”标签。
8. 确认入库：先 proposal，再 apply；支持 undo batch。

## 3. 绝不做的

- 不把每页 PDF 当一道题；
- 不把整页截图塞进题干；
- 不用模型生成的答案冒充官方答案；
- 不在无答案时硬凑解析；
- 不重复导入同题不同页。

## 5. 与 Furnace 内部数据

- gaokao-library/manifest.json 只做来源清单；
- 题目入库另走 question_unit；
- 入库前的 proposal/undo 复用 material_intake_batches/proposals；
- 已入库题目用“题库质量”标签标记缺答案/缺解析/待重生成。

## 6. 验收

- questions 表里不出现“整页 PDF 截图”；
- 每题能追到 source_document + 页码 + 题号；
- 官方答案/解析与模型改写分开；
- 同题不重复；
- 无答案题只登记，不硬做精研。
