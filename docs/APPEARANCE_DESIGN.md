## 2. 待做项与方案

### 2.1 图标（用户点名）

现状：导航栏六到七个图标是**写死的 Material 图标**（`Icons.account_tree_outlined`
之类），无法更换。

**决策 D1**：图标按**语义槽位**配置，而不是"给每个按钮随便换图"。

```jsonc
// 主题文档新增 icons 段
"icons": {
  "tags": "account_tree",
  "thread": "bolt",
  "time": "schedule",
  "knowledge": "psychology",
  "packages": "library_books",
  "ai": "smart_toy",
  "settings": "settings"
}
```

- 槽位**固定**（导航项 + 少数几个高频动作），不从 UI 里抓任意控件的图标——那会变成
  "给每个 widget 一个 id"的泥潭，违背③。
- 取值是 **Material 图标名**（字符串）。用名字而不是码点：可读、可手写、跨版本稳。
- 需要一个**图标选择器**：光让用户敲名字不现实。方案：内置一个按类别分组的常用图标
  网格（约 100–200 个），加一个搜索框按名字过滤。**不联网下载图标包**（违背①，且
  Android 上还要处理缓存）。
- 未知图标名 → 回退到该槽位的出厂图标，不报错（主题文件可能有别处的名字）。

### 2.2 主题色（用户点名）

现状：只有一个 `primary` 色板（7 个固定色）+ 任意取色，由它 seed 出整个配色。
`secondary` 被解析但没用上，`surface` 只能手改 JSON。

**决策 D2**：把配色控制扩到**四个语义色**，都进编辑器：

| 字段 | 作用 | 默认 |
| --- | --- | --- |
| `primary` | 主色（强调、选中） | 已有 |
| `secondary` | 次色（次级强调、徽标） | 由 primary 派生 |
| `surface` | 卡片/面板底色 | 由 primary 派生 |
| `background` | 页面底色 | 已有 |

**决策 D3**：色板从 7 个扩到**按色相分组的 24 个**（红橙黄绿青蓝紫灰各深浅两档），
仍保留任意取色。理由：7 个在实际用起来明显不够，但做一个完整 HSV 拾色器对手机端
不友好；分组色板 + 取色是效果与成本的最佳折中。

**决策 D4**：加一个 `contrast` 滑杆（0–100），微调 ColorScheme 的对比度
（`ColorScheme.fromSeed` 支持）。这是"同一个主题色看起来太淡/太重"最直接的解，
且实现成本几乎为零。

### 2.3 字体（用户点名）

现状：能填字体族名，但没有字体文件导入。**在 Android 上填一个系统里没有的族名 = 没反应**，
这正是"假控件"的另一种形式。

**决策 D5**：实现字体文件导入（`.ttf` / `.otf`），复制到应用数据目录，运行时用
`FontLoader` 注册，并让主题引用导入时给的族名。

- 导入界面要**立刻显示预览**（一段示例正文），否则用户无法判断选对没有
- 每个主题最多带 **2 个**导入字体（界面 + 正文），避免主题包无限膨胀
- 导入的字体**随主题导出**（放进 `.tfpkg` 的附件区），否则"导出主题"换台机器就失效
- 字体文件大小上限（比如 20 MB/个）并明确提示

**决策 D6**：字体设置里同时提供一个**系统字体族下拉**（从平台可取到的族名里选），
与"导入字体"并列。理由：多数人只想要"换成正黑/等宽"，不该被迫去下载字体文件。

### 2.4 主题包的完整性

**决策 D7**：主题文档自身要能**自包含**（颜色 + 图标 + 字体的引用），
`.furnace-theme.json` 单文件导出时：不含二进制（字体/背景图）时明确提示
"该主题引用了 2 个本机文件，导出为单文件将丢失它们"，并提供"导出为 .tfpkg 附件"选项。
不静默丢文件——静默丢正是"换台机器就变样"的根源。

## 3. 实施顺序

| 阶段 | 内容 | 为什么这个顺序 |
| --- | --- | --- |
| P1 | 图标槽位 + 选择器 | 用户点名，纯数据 + 一个选择界面，风险最低 |
| P2 | 四个语义色 + 24 色板 + 对比度 | 纯参数，无新依赖 |
| P3 | 系统字体族下拉 | 比字体文件导入简单得多，先解决多数场景 |
| P4 | 字体文件导入 + 预览 + 随主题导出 | 依赖 FontLoader 与打包改动，放最后 |

---

## 4. 需要用户确认的

1. **图标槽位的范围**：我建议只做"导航项 + Thread 顶栏动作 + 设置里的少量高频项"，
   约 10 个槽位。要不要更多？（每多一个槽位，编辑器就多一行，收益递减）
2. **内置图标库规模**：100–200 个够吗？还是希望"能选所有 Material 图标"（那需要
   把整份图标表打进应用，约 +1.5 MB，且选择器会变成大海捞针）。
3. **字体文件导入值不值得做**：它是最贵的一项（注册、预览、打包、Android 字体路径
   差异）。如果你主要用系统字体，P3 就够，P4 可以砍掉。
4. **主题是否要能"只改一处颜色就全局变"**：现在是 seed 派生，改 primary 会连带
   改变很多派生色。如果你希望"只改背景、其它一律不动"，那 D2 的语义色要改成
   **直接覆盖**而不是 seed 派生——这是两种不同的设计，得先定。
