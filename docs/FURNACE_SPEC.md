项目名称：Threadflow

项目定位：面向高密度信息工作者的本地化生产力工具，融合动态优先级事件流、日程管理、间隔重复记忆与思维导图四大核心功能。

目标平台：Windows 10/11 及 Android 8+（基于 Flutter 框架）。

核心原则：

1. 本地优先：所有数据完全存储在用户本地，不上传任何云端服务器。
2. 文件化传输：支持将全部数据打包为单个加密/压缩文件，支持导入与导出。
3. 高自定义：界面外观、排序规则、复习模板均支持用户深度自定义。

## 1. 核心模块功能规格

### 1.1 Thread（动态优先级事件流）

功能定义：管理“待办事项”的核心模块。事件通过综合算法自动排序，帮助用户决定“当下做什么”。

#### 1.1.1 事件数据结构（Event Model）

- 固定字段（均为可选，缺省即算法忽略）：
  - `id`：唯一标识。
  - `title`：事件标题（文本）。
  - `estimated_duration`：期望用时（分钟，整数）。
  - `expected_time`：期望时刻（DateTime，软约束）。
  - `deadline`：截止时刻（DateTime，硬约束）。
  - `energy_required`：精力要求（整数 1-10，UI 提供详细刻度参考）。
- 动态字段：
  - `tags`：标签列表。每个标签保留完整树形路径（如 `["文化课/学科/语文/作文"]`），UI 默认折叠父级路径，仅显示末级，悬停或点击可展开完整路径。

#### 1.1.2 标签系统

- 来源：用户手动创建，或从 Mindnet 模块导入整个“系”（即树形结构）。
- 导入行为：保留完整的树形层级路径作为标签字符串，供精确查询。

#### 1.1.3 优先级排序算法（核心）

- 触发方式：仅限用户手动点击“更新与排序”按钮触发，禁止自动轮询。
- 状态输入（顶栏）：
  - 当前精力水平（1-10）。
  - 当前主要目标（自由文本或从 Mindnet 节点导入）。
  - 上述状态持久化存储，若距上次更新时间超过 2 小时，点击按钮时弹窗询问确认或修改。
- 算法公式（加权综合评分）：

  总分 = (紧急度 × 0.4) + (目标匹配度 × 0.3) + (状态适配度 × 0.2) − (同类疲劳惩罚 × 0.1)

  - 紧急度：基于 deadline 倒计时计算，采用指数增长曲线，时间越近分数急剧升高。
  - 目标匹配度：事件所带标签与“当前主要目标”文本/节点重合度（简单的关键词命中或树形交集计数）。
  - 状态适配度：`energy_required` 与用户当前精力的差值越小分越高；预估用时与当前可用窗口的匹配度。
  - 同类疲劳惩罚：查询历史完成记录，若刚刚完成（1 小时内）的同类标签事件较多，则扣分（基于时间衰减恢复）。
- 硬性约束（置底标红）：
  - 计算 实际可用时间 = `(deadline − 当前时间) − (该时间段内所有 Time 日程块的总时长)`。
  - 若 `estimated_duration > 实际可用时间`，该事件强制标红置底，提示“时间不足”，不参与正常排序。

#### 1.1.4 任务模板与批处理

- 模板：可将一组参数（时长、标签、精力）保存为模板，创建任务时套用。
- 批量修改：支持按标签筛选事件，批量修改其数值字段（如将所有“阅读”类任务从 20 分钟改为 15 分钟）。

### 1.2 Time（日程与时间管理）

功能定义：管理用户的“硬性时间块”（如上课、开会、通勤），为 Thread 提供不可用窗口数据。

#### 1.2.1 日程块数据结构（Schedule Block）

- `id`、`title`、`start_time`、`end_time`、`repeat_rule`（不重复/每天/每周等）。
- 标签支持：日程块同样可挂载标签（如“碎片时间”“深度时间”），用于软性匹配推荐。

#### 1.2.2 交互与视图

- 提供标准日历视图（日/周/月切换）。
- 点击空白区域或已有时间块，弹出浮窗进行创建或详细编辑。

#### 1.2.3 与 Thread 的交互逻辑

- 冲突处理：当事件截止时刻或期望时刻落在日程块内，系统仅弹窗警告用户。
- 便捷调整：警告浮窗内提供“移至该日程块之前”和“移至该日程块之后”的一键按钮（同时调整期望时刻与截止时刻，确保预估用时能完整放入空闲区）。
- 时间计算：Time 模块实时向 Thread 提供“当前时刻”及“指定区间内的日程块占用总时长”。

### 1.3 Knowledge（间隔重复记忆系统）

功能定义：类似 Anki/百词斩的知识记忆工具，强调对“加工后的词条”进行智能测试。

#### 1.3.1 词条数据结构

- 包含富文本正文、结构化的挖空位置记录、历史复习日志。
- 格式支持：内置富文本编辑器，支持导入/导出 Markdown 和 JSON 格式。

#### 1.3.2 复习与挖空机制（核心）

- 自由挖空：系统按概率决定是否创造“新空位”。若决定创造，则生成历史中未出现过的挖空位置；若该词条无可挖新空位，打内部标记，仅从历史方式抽取。
- 题目形式：选择题（单选、多选、有序多选）、填空题、简答题（严格模式：逐字符自动比对；非严格模式：用户自判正误）。
- 错题处理（强制绑定）：
  - 答错 → 该挖空方式立即强制生效，并让用户即时重做一次。
  - 短间隔（如 10 分钟后）再次出现，直到连续两次正确，强制状态解除，回归自由挖空。
- 间隔重复算法：采用 FSRS（Free Spaced Repetition Schedule）算法，完全本地计算，基于用户历史复习数据动态调整下次出现间隔。

#### 1.3.3 Mindnet 联动机（图谱扩散）

- 当一张卡片答错时，读取其在 Mindnet 中关联的节点图谱。
- 提权规则：距离为 1（直接父子/兄弟）的卡片抽取权重 ×1.8；距离为 2 的卡片权重 ×1.3。
- 衰减：该提权效果仅持续 3 次抽卡周期，之后自动恢复。

### 1.4 Mindnet（思维导图）

功能定义：成熟的、可编辑的思维导图工具。

- 1.4.1 编辑能力：支持节点增删改、拖拽移动、建立连接关系（父子/兄弟）。
- 1.4.2 导入导出：支持导入/导出标准格式（如 OPML、FreeMind（.mm）格式）。
- 1.4.3 与 Thread 标签系统的接口：
  - 用户可选择 Mindnet 中的任意节点（作为“系”），一键将其路径及其所有子节点路径导入 Thread 的标签系统，作为可用的树形标签。
  - 用户可将 Mindnet 节点设为“当前目标”，Thread 算法将提升该路径下标签事件的权重。

## 2. 模块间联动机制（闭环）

| 触发源 | 目标模块 | 动作描述 |
| --- | --- | --- |
| Knowledge | Thread | 复习中发现词条错误或难以记忆，点击“生成任务”按钮，自动创建一条 Thread 事件（如“查阅某概念资料”），内容自动带入词条标题。 |
| Mindnet | Thread | 将思维导图节点/系导入为标签体系；将节点设为当前目标权重。 |
| Time | Thread | 提供当前时间及日程块占用数据，用于计算硬性时间约束。 |
| Thread | History（隐式） | 完成任务后自动记录，供“疲劳惩罚”算法和 Knowledge 上下文参考。 |

## 3. 数据持久化与打包传输

- 存储方案：采用 SQLite（结构化数据）+ 本地文件系统（富文本图片、背景图、主题文件）。
- 打包导出：点击“导出工作区”，系统将 SQLite 数据、附件、主题配置全部压缩为单个 `.tfpkg`（Threadflow Package）文件。
- 导入载入：选择 `.tfpkg` 文件，系统解压并覆盖/合并当前数据（具体合并策略提供“覆盖”与“追加”选项）。

## 4. 用户界面与外观自定义系统

- 4.1 可自定义元素：
  - 字体：系统 UI 字体与编辑器正文字体可分别设置。
  - 布局：页面缩放（80%~150%）、界面语言（内置中/英，支持扩展）。
  - 视觉：主题色（主色/辅色）、背景颜色、背景透明度、背景图片（使用本地文件，软件自动复制至内部目录）。
  - 动态：动画效果开关（如列表滑入淡出）。
- 4.2 主题管理：
  - 所有配置打包为一个 JSON 主题文件。
  - 内置官方深色与浅色默认主题。
  - 用户可新增自定义主题并随时切换。
  - 支持主题的导入与导出，方便分享。

## 5. 技术栈建议（供 Agent 编码参考）

- 框架：Flutter (≥3.16)
- 状态管理：Riverpod 或 Bloc（推荐 Riverpod，轻量且灵活）
- 本地数据库：sqflite 或 drift（推荐 drift，类型安全）
- FSRS 算法：参考 ts-fsrs 逻辑移植为 Dart 实现，或使用 Dart 科学计算库自行实现三参数模型。
- 思维导图渲染：可基于 flutter_treeview 或自定义 CustomPainter，确保节点拖拽流畅。
- 富文本编辑：flutter_quill 或 super_editor。
- 文件压缩：archive 库用于打包/解包 `.tfpkg`。
- 日历 UI：table_calendar 结合自定义浮窗。

## 6. 交互细节补充

- 顶栏布局（常驻）：左侧显示当前“主要目标”与“精力水平”状态，右侧为“更新与排序”按钮。
- 状态保持：若精力/目标长时间未更新（>2 小时），点击按钮时弹出确认对话框，用户确认或修改后，系统记录新的时间戳。
- 时间不足警告：在 Thread 列表底部或事件卡片上，以醒目的红色标签显示“该任务时间不足（需 X 分钟，可用 Y 分钟）”。
